## Why

Static analyzers like Semgrep are excellent at spotting insecure patterns, but their output is often terse and technical — rule names and security jargon that a junior developer can't always translate into a concrete fix. `ai-vuln-scanner` takes each finding and enriches it with a plain-language explanation and a suggested fix, generated by an AI model that runs **locally and for free** via [Ollama](https://ollama.com) — no paid API, no code leaving your machine.

## Features

- **Static scanning with Semgrep**, using its auto-config rule set (`--config=auto`) across multiple languages.
- **Local AI explanations and fixes** via Ollama (`qwen2.5-coder:7b`) — no API keys, no external services.
- **Severity filtering** with `--min-severity` (`LOW` / `MEDIUM` / `HIGH` / `CRITICAL`), so you can focus on what matters.
- **Color-coded terminal output** by severity (red for CRITICAL/HIGH, yellow for MEDIUM, green for LOW).
- **Markdown or HTML reports** — the HTML report is fully self-contained (embedded CSS, dark "security console" theme, zero external dependencies) — the format is picked automatically from the `--output` file extension.
- **Format-tolerant LLM parsing**: a regex tolerant to formatting drift plus a Markdown-code-block fallback heuristic, so explanation/fix separation still works even when the model doesn't follow the prompt's format exactly.
- **`--skip-ai` mode** to run the scanner only, useful for fast iteration or CI-style checks.

## Installation

```bash
# 1. Clone the repository
git clone <repo-url>
cd ai-vuln-scanner

# 2. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate

# 3. Install Python dependencies
pip install -r requirements.txt

# 4. Install Semgrep (already in requirements.txt, but can be installed standalone)
pip install semgrep

# 5. Install Ollama
# See https://ollama.com/download for OS-specific instructions

# 6. Start the Ollama service (if it doesn't start automatically)
ollama serve

# 7. Pull the model used for explanations
ollama pull qwen2.5-coder:7b

# 8. Install the project in editable mode
#    (required so `import src...` resolves correctly, e.g. when running tests)
pip install -e .
```

## Usage

```bash
python3 -m src.cli TARGET_PATH [OPTIONS]
```

### CLI options

| Option | Description | Default |
| --- | --- | --- |
| `--skip-ai` | Skip the AI layer and only run the scanner. | disabled |
| `--min-severity [low\|medium\|high\|critical]` | Minimum severity to include (case-insensitive). Findings below this level are filtered out **before** being sent to the AI layer or printed. | `low` (no filtering) |
| `--output PATH` | Save the report to `PATH`. Format is inferred from the extension: `.html` → self-contained HTML report, anything else (including `.md`) → Markdown. | none (no report generated) |

### Examples

```bash
# Full scan, with AI explanations and fixes
python3 -m src.cli <path>

# Fast scan, Semgrep only, no AI
python3 -m src.cli <path> --skip-ai

# Only show HIGH and CRITICAL findings
python3 -m src.cli <path> --min-severity high

# Generate a Markdown report
python3 -m src.cli <path> --output report.md

# Generate a self-contained HTML report
python3 -m src.cli <path> --output report.html

# Combine flags: quick CRITICAL-only scan, exported to HTML
python3 -m src.cli <path> --skip-ai --min-severity critical --output report.html
```

Try it against the vulnerable sample app bundled in this repo:

```bash
python3 -m src.cli examples/vulnerable_app
```

## Tests

The project uses `pytest`. Tests exercise the parsing logic (Semgrep result parsing, LLM response splitting) using in-memory example data — no live Semgrep scan or running Ollama instance required.

```bash
# Requires editable install (see Installation, step 8)
pytest
```

## Architecture

The project is organized into layers with clear, single-purpose responsibilities:

```
Scanner (Semgrep)  →  Data models (Pydantic)  →  AI layer (Ollama)  →  CLI (Click)  →  Report generator (Markdown / HTML)
```

- **`src/scanner/semgrep_runner.py`** — runs Semgrep against the target path and parses its JSON output into `Finding` objects.
- **`src/scanner/models.py`** — Pydantic models (`Finding`, `ExplainedFinding`, `Severity`) that shape and validate data as it flows between layers.
- **`src/ai/`** — prompt construction (`prompts.py`) and the Ollama call with tolerant response parsing (`explainer.py`).
- **`src/cli.py`** — command-line entry point (Click); orchestrates scanning, severity filtering, AI explanation, and result printing.
- **`src/report.py`** — generates the Markdown or HTML report from explained findings; severity ordering/counting logic is shared between both formats.

## Known limitations

- Not designed to reliably detect hardcoded secrets (API keys, passwords); it relies entirely on Semgrep's own rules for that.
- AI processing is **sequential**, not parallel — scanning a project with many findings can take a while.
- AI-generated explanations are tuned and tested primarily for **Python code, in Spanish**; quality may vary for other languages.
- Requires **Ollama running locally** with the model pulled; without it the AI layer won't work (though `--skip-ai` remains available).

## Tech stack

- **Python** — project language.
- **Semgrep** — static analysis engine.
- **Ollama** — local execution of the AI model (`qwen2.5-coder:7b`).
- **Pydantic** — data modeling and validation.
- **Click** — command-line interface.
- **pytest** — unit tests for Semgrep parsing, LLM response parsing, and report generation.
